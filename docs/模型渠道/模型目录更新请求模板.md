# 模型目录更新请求模板

本模板用于提交供应商模型目录、官方价格、能力标签或生命周期的更新请求。一次请求只描述可由官方资料核验的事实；渠道启用、分组发布和商业定价另行处理。

## 请求信息

| 字段 | 填写内容 |
| --- | --- |
| 标题 | `供应商：模型目录更新` |
| 提交日期 | `YYYY-MM-DD`，注明时区 |
| 提交人 | 姓名或 GitHub ID |
| 影响仓库 | `router`，按需补充适配器仓库 |
| 变更类型 | 新增模型、价格调整、能力调整、状态调整、下线标记 |
| 紧急程度 | 常规、计费风险、下线风险、安全风险 |

## 官方证据

每个结论必须附供应商一手来源。动态控制台截图只能作为辅助材料，不能替代可访问的官方链接。

| 项目 | 链接 | 核验时间 | 摘要 |
| --- | --- | --- | --- |
| 模型目录 | `https://...` | `YYYY-MM-DD HH:mm Z` | 模型 ID、可用状态、接口范围 |
| 价格页 | `https://...` | `YYYY-MM-DD HH:mm Z` | 价格单位、币种、标准价、缓存价、批量价 |
| 生命周期公告 | `https://...` | `YYYY-MM-DD HH:mm Z` | 生效日、弃用日、替代模型 |
| API 文档 | `https://...` | `YYYY-MM-DD HH:mm Z` | 请求端点、输入输出模态、限制 |

无法确认的信息必须填写“待确认”，不能以 `0` 代表免费或未知。

## 模型变更清单

每个模型一行。`Router 模型 ID` 必须是供应商官方模型 ID，不能写渠道私有别名。

| 供应商 | Router 模型 ID | 变更 | 当前状态 | 目标状态 | 模型形态 | 官方端点 | 能力标签 | 替代模型 | 官方来源 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `openai` | `example-model` | 新增 | 不存在 | `active` | `text` | `/v1/responses` | `reasoning` | - | `https://...` |

模型形态只能是 `text`、`image`、`audio`、`video`、`embedding`。能力标签只能补充事实，例如 `reasoning`、`vision`、`tool_calling`、`realtime`、`structured_output`、`file_input`；它们不能替代端点声明。

## 价格变更清单

价格统一按 Router 的 `per_1k_*` 单位提交。请把供应商原始单位和换算结果都填出，以便复核。

| 供应商 | 模型 ID | 条件 | 计费组件 | 原始价格 | Router 输入价 | Router 输出价 | 单位 | 币种 | 生效时间 | 官方来源 |
| --- | --- | --- | --- | --- | ---: | ---: | --- | --- | --- | --- |
| `openai` | `example-model` | `mode=standard` | `text` | `$10 / 1M input tokens` | `0.01` | `0.05` | `per_1k_tokens` | `USD` | `YYYY-MM-DD` | `https://...` |

规则：

1. 基础输入价和输出价写入模型默认价。
2. 缓存读取、缓存写入、批处理、长上下文、图像、音频、视频等差异写入 `price_components`，并提供可匹配的 `condition`。
3. 同时调整默认价和实际会命中的价格组件；只改默认价会导致计费仍使用旧组件价格。
4. 无法由 Router 当前请求元数据稳定判定的条件不能自动计价，应记录为待设计项。
5. 价格变更不得改写 `channel_models` 的人工覆盖价。

## 路由兼容性核验

| 核验项 | 结论 | 证据或待办 |
| --- | --- | --- |
| 协议适配器 | 已支持 / 需要新增 | 说明 OpenAI、Anthropic、Gemini 等协议归属 |
| Router 端点 | 已支持 / 需要新增 | 列出真实请求路径 |
| 请求格式 | 兼容 / 需要转换 | 说明字段、流式、工具调用、文件输入差异 |
| 响应和 usage | 兼容 / 需要转换 | 说明 token、缓存 token、音视频用量字段 |
| 模型测试 | 已验证 / 待渠道验证 | 记录渠道、模型、端点、结果链接 |

供应商目录 migration 不得自动启用渠道模型、渠道端点或分组模型。发现新模型只意味着它可供管理员选择，不代表已有渠道可以调用。

## 实施范围

预计修改：

1. `internal/admin/model/provider_migration_snapshot.json`
2. `internal/admin/model/migration_runner.go` 中新增唯一版本号的 migration
3. 模型类型、端点归一化或协议适配代码，仅在官方接口确有变化时修改
4. 目录加载、价格和 migration 测试
5. 本次核验记录

不在本请求范围：渠道自动发布、分组自动发布、渠道人工价格覆盖、套餐售价、历史账单回算。

## 验收清单

- [ ] 官方模型 ID、状态、端点和价格均有一手来源。
- [ ] 未确认价格未写成零价格。
- [ ] 新 migration 版本唯一，重复执行幂等。
- [ ] migration 只刷新供应商目录，不改写渠道或分组配置。
- [ ] 默认价格和可命中价格组件一致。
- [ ] 已新增或更新目录测试。
- [ ] `go test ./internal/admin/model` 通过。
- [ ] 已更新本次核验记录和 `docs/README.md` 入口。
